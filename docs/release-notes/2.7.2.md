# v2.7.2

## Fixed

- Client sessions now close after 15 minutes without traffic in either
  direction. Set `--client-idle-timeout` to change the interval, or use `0`
  to disable it. Partial reads and writes extend the deadline, including
  fragments of a FakeTLS record. Idle connections with a rejected MTProto
  secret also release their slot. TCP keepalive detects dead peers and the server
  warns when it reaches the connection limit. HTTP/2 media sessions also log
  when they close. (#179)
- A pinned MTProto tier tries available proxies before retrying any in
  cooldown. (#174)
- Outbound FakeTLS uses a padded TLS 1.3 ClientHello and sends the client
  ChangeCipherSpec before the MTProto init. A peer that never replies to the
  ClientHello now times out. (#175, #177)

## Android

- The app can start the proxy with the saved arguments after reboot. It keeps
  its generated secret across starts so Telegram can reuse the same link.
  Explicit `--secret` values take precedence. (#181)
- Copy the proxy link from the app to enter its MTProto settings in
  Telegram X during sign-in. (#178)
- The Android guide explains how to build a console binary with the NDK so
  it uses Android's DNS resolver. (#173)

## OpenWrt

- The OpenWrt CI and release jobs use Ubuntu 24.04 for the pinned SDKs.

## Documentation

- The Cloudflare guide explains why `--cf-disable-tls` selects WebSocket on port 80.
  Cloudflare requires TLS for client-facing HTTP/2 even when the origin supports h2c.
