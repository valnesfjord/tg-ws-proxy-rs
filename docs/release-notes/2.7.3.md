# v2.7.3

## Fixed

- HTTP/2 media frames that use plain (unobfuscated) `padded intermediate`
  framing are accepted with the reference's padding budget, `MAX_PLAIN_PADDING`
  (256 bytes), instead of 15. The client pads up to that limit whenever the
  transport underneath is already encrypted, which is exactly the media case:
  every such frame was rejected as `invalid padded MTProto packet` and the
  session closed before it sent anything. On a router measured over two days,
  6 689 of 13 791 media sessions died this way. The declared-length bound
  widened with it (`MAX_PACKET` plus the same budget); the encrypted branch
  keeps its 15-byte limit.
